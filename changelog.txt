Changelog
=========

Every user-visible change lands here in the same commit that makes it,
newest version first. Entries are written from measurements rather than
intentions: what was observed, and why it mattered. A reader a year from
now needs the evidence, not the plan -- "two consecutive runs differed in
exactly one path" is worth more than "improved caching". Prose, hard-
wrapped at 72 columns, US English.

0.5.0
-----
- The live-installation tests are selected by a marker: `pytest -m
  live`. The documented `-k "pin or live"` matched names, not intent --
  on 0.4.0 it selected 23 tests, 20 of which run everywhere anyway, and
  missed test_the_recorded_app_version_matches_the_bundle, one of the
  four it was meant to find. Markers are now strict, so a misspelled one
  fails instead of silently selecting nothing.
- The live tests read the store the way the tool does, through
  SqliteSource, so the production open path -- a URI containing
  "Application Support", mode=ro on a WAL database, query_only -- is
  finally exercised on the one machine that has a real store. The column
  comparison reports every difference at once: against 1.6.957 the old
  test stopped at the new FolderMeetings table and hid the column
  changes on Folders and SharedNotes behind it.
- Four tests promised more than they checked. The world-readable test
  inspected only the finished mode, which a write-then-chmod
  implementation also passes; it now captures the mode each file is
  created with. The redaction test asserted that "[redacted]" appeared,
  not that the secret was gone, and never tried the cloud backend's own
  bare-token header form. The retry test accepted any count above one;
  it now requires exactly four attempts. And pacing had no test at all,
  because every test set the interval to zero -- two back-to-back
  requests must now cost exactly one 0.25-second wait. Fixtures building
  meeting directories from hostile ids no longer create them outside the
  test's scratch directory, which they had been doing.
- Re-pinned against Wispr Flow 1.6.957 at migration 157, five migrations
  past 1.6.897/152. New: FolderMeetings, which files meetings into
  folders; Folders.meetingCount and memberCount; SharedNotes.meetingId
  and via. All four were already being archived -- the reader follows
  PRAGMA table_info -- so what was stale was the declaration. Three of
  the five new migrations are dated a week before the migration that was
  latest at the old pin and shipped after it, so SchemaPin.latest is a
  label rather than a version and the README no longer assumes migration
  names arrive in order. The digest over the whole set is what catches
  that, as designed.
- Composite primary keys are modeled. FolderMeetings is keyed by
  (folderId, meetingId), and a key with more than one column used to be
  reported as no key at all: the table's rows had no identity, its key
  was never checked for drift, and its snapshot followed SQLite's scan
  order, which a VACUUM may change -- rewriting the file with nothing
  new in it. Snapshots now sort by key and then by content, which for a
  unique single-column key is exactly the old order, so no existing
  snapshot is rewritten. Key columns now count as required, and a key
  that changes shape is breaking drift.
- Losing a column a renderer reads is breaking drift. Meetings declared
  only id, title, createdAt and modifiedAt as required, so a migration
  dropping summary was additive and the render gate stayed off. Measured
  on 0.4.1: after the column went, a sync that re-read the meeting --
  --full, or any later edit -- rewrote meeting.md and raw/meeting.json
  without the summary; only summary.md kept it, because an empty summary
  is never rendered. summary, notes, speakerMap, participantNames and
  transcriptDeletedAt are now required on Meetings, the dictation text
  cascade and app on History, and replacement, isSnippet and isDeleted
  on Dictionary.
- Rows Wispr Flow deletes are kept, for every table archived as a whole
  file. The dictionary, todos, each day of dictation and every table
  archived generically were rewritten from the rows upstream held at
  that moment, so a hard-deleted row vanished from the archive on the
  next run that touched its file -- and verify, comparing that file's
  own count with the table's, called the result consistent. Measured on
  0.4.1: two dictionary entries and two same-day dictations, one of each
  deleted upstream, one plain sync, both gone. Each file still mirrors
  upstream exactly, so 0.4.x archives need no migration; what upstream
  drops now moves first to a <file>.removed.ndjson ledger beside it, one
  verbatim row per line with the date it was first seen gone. Ledgers
  are only ever appended to, at the byte level, and record each row once
  however many runs see it gone, so a second run writes nothing. A table
  emptied upstream becomes an empty file and a full ledger.
- Dictation days outside the re-read window are watched too. Each run
  now reads every History row's identity and timestamp -- two columns,
  cheap -- and rewrites any day whose membership moved, carrying forward
  the rows the window did not re-read. Before, three kinds of dictation
  could be lost: one deleted on a day the window had passed (never
  noticed); one stamped exactly on the window's midnight boundary, which
  the strict `>` query never returned while its day was rewritten
  without it; and one with no timestamp at all, which no windowed query
  can match and only --full ever found. --full itself rewrote every day
  from scratch, which made it the most destructive run there was; it is
  now as safe as any other.
- dictionary.md lists entries deleted upstream in a "Removed upstream"
  section with the date each went, and a day's dictation log keeps a
  removed entry at the time it was spoken, marked as removed. With
  nothing removed both documents are byte-for-byte what 0.4.x wrote, so
  the upgrade does not rewrite them. Sharded tables' rows are ordered by
  date and identity rather than scan order, which may rewrite a few
  shards once; a dictation day log no longer stops the run when numWords
  holds something that is not a number.
- What upstream empties is kept, not only what it deletes. A record that
  survives upstream can still lose what it held -- a column a migration
  drops, a summary someone clears, a list that shrinks -- and every
  archived payload was simply replaced. Measured on 0.4.1: a meeting
  whose summary went away upstream lost it from raw/meeting.json on the
  next sync that re-read the meeting. A replacement that loses content
  now files the version it replaces first: under
  superseded/<kind>/<key>/, content-addressed so it is kept once, for a
  meeting's raw/meeting.json, a note's raw payload, a calendar event,
  the account's JSON and each cloud endpoint; and as a superseded_at
  line in the ledger for a row of a table archived as a whole file. An
  edit that replaces one value with another loses nothing and is
  mirrored as before, and churn columns do not count.
- The account's writing samples and rewrite prompts are archived raw, as
  account/context.json. They existed only as the two Markdown files
  rendered from them, which broke the rule every other entity keeps: raw
  first, so a rendering can always be rebuilt and nothing depends on
  one.
- A record deleted upstream is flagged on the next run, not the next
  --full run. Absence used to be established only by a --full pass,
  since a watermarked read has not seen what it skipped, so a meeting,
  note or calendar event deleted upstream stayed unflagged -- and
  verify, counting rows against entries, reported the archive as broken.
  Measured on 0.4.0, and unchanged in 0.4.1: one meeting deleted, one
  plain sync, then `verify` printed "Meetings: 1 in source, 2 archived |
  archive has problems" and exited 1, the same false alarm 0.3.1 fixed
  for the flagged case. Each run now reads the three tables' keys -- one
  column each, cheap -- flags what is gone, and re-reads what has come
  back.
- The same key scan re-reads any record the index lost track of, without
  --full. A dry run before 0.4.1 could leave an index entry with no file
  behind it and the watermark already past the record; only --full
  recovered it. Now the next sync does.
- verify reconciles by identity, not by count. Meetings, notes and
  calendar events are checked record by record -- calendar events were
  only ever counted -- and an index entry with no file behind it no
  longer counts as archived. The dictionary and todos are checked row by
  row against the snapshot and its ledger together. A record gone
  upstream since the last sync is reported, not failed: the next sync
  flags it. A table whose key column is gone is reported as not
  reconciled rather than as every record missing.
- wispr-export render rebuilds every local document, not only meetings'.
  Breaking drift holds back notes, dictionary.md and dictation logs too,
  and the run tells the operator to re-render once the declaration is
  fixed -- advice that repaired meetings and nothing else. Measured on
  0.4.0: a held-back note survived both `render --force` and a plain
  sync, and only `sync --full` rebuilt it. Render now builds each
  document with the same function sync uses, so re-rendering a healthy
  archive writes nothing, and it reports each kind of document on its
  own line.
- A document breaking drift holds back is marked stale, so the next
  ordinary sync after the declaration is fixed rebuilds it, as render
  does. It used to stay stale until a --full run, because its record's
  content had not changed and a plain sync never looked at it again.
- Re-rendering no longer strips a soft-deleted meeting's tombstone.
  Measured on 0.4.1: after `wispr-export render`, a meeting deleted in
  Wispr Flow lost `deleted: true` and its "Deleted in Wispr Flow" banner
  from meeting.md, because the record render rebuilt it from never
  carried the flag.
- render --force is accepted and hidden. It never forced a rewrite --
  every write is compare-then-write, and rewriting identical bytes would
  only move mtimes -- it only reported every meeting as written. It now
  says it is no longer needed.
- Every write goes through a temp name no one can predict. Temp files
  were <name>.tmp, a fixed name opened with O_TRUNC, so two writers of
  one file -- two runs refreshing the MCP token at once -- could
  interleave their bytes in one inode, and a file planted at that name
  was truncated and written through. Each write now opens a fresh hidden
  name with O_EXCL and O_NOFOLLOW, renames it into place, and removes it
  if anything fails, which also ends the debris a failed write used to
  leave. copy_file_secure, which carries meeting audio, gets the same
  open and an fchmod on the descriptor: it was the one write the 0.4.0
  fix missed, and still opened a predictable name with neither flag.
- Two syncs can no longer write one archive at the same time. Each
  loaded the index, changed it and saved it, so whichever saved last
  silently dropped the other's records from the index while their files
  stayed on disk. A sync or a render now takes an advisory lock on .lock
  in the archive root and a second one exits 1 saying why. Dry runs and
  verify take no lock.
- The response cap counts what a body inflates to, and this tool now
  does the inflating. 0.4.0 capped httpx's decoded output, but httpx
  inflates each network read whole before handing it over, and chains
  one decoder per declared encoding. Measured on 0.4.1: a 590-byte body
  declaring `Content-Encoding: gzip, gzip` allocated 558 MiB before the
  64 MiB cap refused it, and 32 KB of gzip arriving in one read peaked
  at 77 MiB against a 1 MiB cap. No inflation step may now produce more
  than the cap still allows -- that body peaks at 2 MiB -- only gzip and
  deflate are offered, and a response declaring more than one encoding,
  or one this client never offered, is refused before it is read.
- A body too large or too deeply nested is that request's failure, not
  the run's. json.loads raises RecursionError, not ValueError, past a
  few thousand levels, and neither client caught it; nor did the MCP
  client catch a reply over the cap, which the REST client had always
  recorded against its endpoint. Measured on 0.4.1: 100 kB of brackets
  from either backend, or one oversized MCP reply, ended the run with a
  traceback. Each is now recorded against the endpoint or call that
  returned it, and the pass goes on.
- Retry-After is read in both its forms, and a value that says nothing
  usable no longer means "now". Measured on 0.4.1: -5 and nan both
  became a zero wait -- an immediate retry against a server that had
  just asked for a pause -- and an HTTP date was ignored. Unusable
  values fall back to the backoff ladder; dates are honored up to the
  same 60-second ceiling as seconds.
- The MCP backend no longer loads the borrowed credential's module. It
  took its retry constants from cloud_api, which imports cloud_auth, so
  importing the MCP backend imported the code that reads Wispr Flow's
  own session -- measured in a fresh interpreter on 0.4.1 -- while the
  test asserting that the two never meet scanned source text and
  passed. Retries, pacing and the cap now live in transport.py, which
  both clients share, and the separation is asserted on what Python
  actually imports.
- The cloud client's tests sent their requests through a hand-built
  httpx client carrying a Bearer scheme the real one never sends, so no
  test saw the headers the service receives. Both clients now take an
  injected transport, and the tests open them exactly as a run does.
- A stored MCP token is sent only to the endpoint it was minted for.
  Measured on 0.4.1: with WISPR_MCP_ENDPOINT overridden to another host,
  the stored production access token was handed to the MCP client
  without a single check, to be sent there as a Bearer. The token store
  now records the resource beside the issuer; a run against any other
  endpoint refuses the tokens, before any request, and says to log in;
  and a refresh token goes only to the issuer that minted it. A store
  written by 0.4.x has no resource, and is adopted for the shipped
  endpoint and issuer only -- anything else asks for a login.
- OAuth discovery checks every hop instead of following it. Measured on
  0.4.1: a resource document describing another resource was accepted,
  and its value became the resource a token was scoped to; a token
  endpoint on another host and an authorization endpoint over plain
  http were both followed. The resource document must now name the
  configured endpoint exactly, the shipped endpoint must name the
  shipped issuer unless WISPR_ALLOW_ENDPOINT_OVERRIDE is set, and every
  endpoint the issuer advertises must be https on its own host.
- `wispr-export login` survives whatever can reach a loopback port.
  Measured on 0.4.1: the listener acted on whichever request came
  first, so a favicon request ended the login as a timeout, an error
  without the login's state ended it as a refusal, a non-ASCII state
  raised TypeError, and one idle connection held the listener past its
  own deadline for as long as it stayed open. The port was also bound
  only after the browser had been sent, so a browser already signed in
  found nothing listening. The listener is now bound first, acts only on
  /callback with this login's state, turns everything else away without
  ending the login, drops a connection that sends nothing after ten
  seconds, and checks RFC 9207's iss when the server promises it. Its
  pages no longer claim success whatever happened.
- Text from an authorization server or the login listener reaches the
  terminal as text. Measured on 0.4.1: an error description of
  \x1b[2J\x1b[H was printed intact, escape sequences and all. Every
  diagnostic line now shows control characters and bidirectional
  overrides as escapes, at the same sink that redacts credentials.
- The minted token is handled as a grant, not a cache. Measured on
  0.4.1: a login answered without a refresh token kept the previous
  login's; an access token saved without an expiry was trusted forever;
  and two runs refreshing at once both spent the same refresh token,
  which a server that detects reuse may answer by revoking the grant. A
  login now replaces the refresh token outright, a missing or malformed
  lifetime is read as one hour, and refreshes are serialized across runs
  by a lock beside the token store, so the second run uses what the
  first one minted. A store that cannot be written stops a refresh
  before the refresh token is spent.
- A token the MCP server rejects mid-run is renewed once instead of
  failing every remaining call. A token revoked, or rotated away by
  another run, before its recorded expiry used to end the pass. A 401
  now triggers one refresh and a retry; a second 401 fails as before,
  and a token from WISPR_MCP_TOKEN is never refreshed.
- OAuth requests fail as authorization errors, with a reason. Measured
  on 0.4.1: a network failure during a refresh escaped as
  httpx.ConnectError, metadata without a token endpoint raised KeyError
  at the first refresh, and a 128 MiB metadata document peaked at 270
  MiB before discovery gave up. Every OAuth request is now read under a
  1 MiB cap. 0.4.0's entry said responses were capped on all three HTTP
  clients; until now that was true of two. A refused refresh asks for a
  login, and a server error no longer does.
- Ctrl-C stops the run. Measured on 0.4.1: after Ctrl-C interrupted the
  local pass, the run went on to contact both remote services. A remote
  pass that failed unexpectedly also lost the other's work: an MCP pass
  that raised discarded the cloud pass's watermarks and drift baseline,
  because the save came after both. Remote passes are now skipped after
  an interrupt, an interrupt during one stops the run with 130, and what
  the passes recorded is saved however they end.

0.4.1
-----
- A dry run could stop every later sync from archiving what it had seen.
  Measured: `sync --dry-run` and then `sync`, against a store holding
  one meeting and one note, archived neither -- the second run scanned 0
  meetings and 0 notes -- and `verify` called the result consistent. The
  dry run advanced its watermarks in memory to count what it would
  write, and the save after the remote passes ran whenever a remote
  backend was selected, which the default `all` always is, credentials
  or not. A dry run now opens the archive read-only and writes nothing:
  not the index, not the state, not the MCP pass's verbatim pages
  (written before its dry-run check), and not a repository's .gitignore.
- A .env in the working directory could still hand the account token to
  someone else. 0.4.0 stopped the search walking up and checked both
  base URLs, but the file was still exported whole. Measured:
  HTTPS_PROXY and SSL_CERT_FILE in it routed every request through a
  proxy it named while trusting a CA it named, which reads the bearer
  token in cleartext whatever WISPR_API_BASE says; XDG_CONFIG_HOME moved
  the MCP refresh token into the working directory; and the same file
  could carry both the redirect and WISPR_ALLOW_ENDPOINT_OVERRIDE,
  making the two-setting consent one accident. A .env now sets only
  WISPR_* options, never the override, and names what it ignored on
  stderr.
- WISPR_INCLUDE_SCREEN_CONTEXT=1 archived screen captures with no
  acknowledgement, although .env.example and SECURITY.md both said
  --i-understand was required. It now is, however screen context is
  switched on.
- A relocation could delete a record. When a record's new path already
  existed, relocate removed it first, on the theory that only an
  interrupted earlier move could have left it there; and it moved
  whatever directory the index named, whether or not that directory
  belonged to the record. With one index entry pointing at another
  meeting's directory -- a restored, merged or sync-conflict copy of
  index.json -- a full sync deleted the first meeting's directory and
  moved the second into its place. A record now moves only out of a path
  named for its own id and only onto a path that is free; anything else
  stays on disk for verify to report. Notes and calendar events follow
  the same rules.
- A damaged index.json was replaced rather than kept. It loaded as empty
  and the next save overwrote it, taking every missing_since and
  transcript_deleted_upstream with it -- facts that exist nowhere else.
  It is now set aside as index.json.corrupt-<time>, the run says so, and
  verify reports it until someone deals with it; .sync-state.json is
  treated the same way. Commands that only read report the damage
  without moving anything.
- A short write could replace the file it was meant to update. os.write
  may write less than it is given -- a nearly full disk does exactly
  that -- and a single unchecked call left a truncated temp file that
  was then renamed over the good one. Writes now loop to completion or
  raise, and a raise leaves the old file where it was.
- The test suite could reach real data. Isolation lived in test_cli.py
  alone, so a test elsewhere calling main(["sync", ...]) from the
  repository root was relying on argparse to stop it; had that check
  regressed, it would have read the real store and used the developer's
  tokens. Every test now runs with WISPR_* and proxy settings cleared,
  the data directory, archive and credential store pointed into a
  scratch directory, and a guard that fails any connection off the
  machine. A bare `pytest` no longer walks into the interactive setup
  either.
- Three of the four live-installation tests fail on the development
  machine, as they are meant to when the app moves: it is now at 1.6.957
  and migration 157, past the 0.4.0 pin. Re-pinning is the next
  release's work, not a hotfix's.

0.4.0
-----
- Re-pinned against Wispr Flow 1.6.897 at migration 152, three weeks and
  three migrations after the 1.6.721/149 the declaration still described.
  New since the pin: a `Folders` table, a `Meetings.recordedMs` column,
  and -- over MCP -- `get_meeting_attendee_emails` replaced by
  `get_meeting_participants_enriched`. Nothing was lost in the interval.
  The reader is driven by `PRAGMA table_info` and synthesizes a spec for
  an undeclared table, so both new shapes were already being archived;
  what was stale was the declaration, and therefore every drift report
  measured against it. The MCP swap is worth noting on its own: the tool
  count stayed at 14, so the count fence saw nothing and the digest over
  input schemas is what caught it.
- The cloud endpoint table was re-probed against 1.6.897 and needed no
  change. All 18 endpoints answer as recorded, including the three that
  are declared knowing they cannot -- meetings 404, notes 405, todos 405.
  Only `CLIENT_PIN.app_version` moved; count and digest are identical.
- Breaking drift now actually skips renderers, which three documents have
  claimed since 0.1.0 and no code did. `blocks_rendering` existed on all
  three drift types and was asserted by six tests, but had no production
  call site and neither sync nor render referenced drift at all.
  Renderers are defensive rather than strict, so a missing required
  column made them render less instead of raising -- and that less was
  being written over the good document from the previous run. The gate is
  narrow: only a rendering that already exists is protected. A record
  first seen during breaking drift is still rendered, because the
  alternative is an index entry pointing at a file nobody wrote.
- Fixed: verify reported a healthy archive as broken when any meeting had
  no resolvable creation time. Dated meetings are filed under
  `YYYY/MM/<record>` and undated ones under `undated/<record>`, one level
  shallower, so the single `*/*/*` glob that looks for unindexed
  directories reached past every undated record onto its `raw/` and
  reported that as data the index had lost. One such meeting was enough
  to print "archive has problems". Found by a test written to cover the
  verify command through `main()`, which nothing had done before.
- Closed a path that sent the account's bearer token to an arbitrary host
  in cleartext. `load_dotenv()` was called with no argument, so it
  searched the working directory and every ancestor; a `.env` two
  directories up resolved `WISPR_API_BASE` to `http://evil.example` and
  nothing objected. Measured, then fixed twice over: the search no longer
  walks up, and both remote base URLs are now checked before a credential
  is attached -- https required, host must be the shipped one unless
  `WISPR_ALLOW_ENDPOINT_OVERRIDE` is also set. SECURITY.md said an
  attacker needed code execution; this needed a file, so the out-of-scope
  clause was wrong and now says so.
- The borrowed credential renders as `Credential(origin=...)` rather than
  as itself. The MCP credential had that guard and this one did not, and
  `CloudClient` is a dataclass holding it as the first field -- so its
  generated repr printed the account's token in full, one
  `pytest --showlocals` away from a log.
- Responses are read under a 64 MiB cap while streaming, on all three
  HTTP clients. Every read previously materialized the whole body, and
  httpx decompresses before returning it, so the bytes on the wire and
  the bytes allocated were not the same number.
- Archive files are 0600 from the instant they exist. The write was
  `write_text` followed by `chmod`, which leaves a real window at the
  umask default -- and that path covered the index, the sync state, every
  rendered document and the MCP token store. Now opened with the mode and
  `O_NOFOLLOW`, so a symlink planted at a predictable temp name is not
  written through either. The test that should have caught the archive
  root's own mode used `rglob("*")`, which does not yield the root.
- A dictionary entry can no longer end its own table row. Pipes were
  escaped and newlines were not, so a phrase from the shared or team
  dictionary -- text this account did not write -- could leave the table
  and land in the document as Markdown.
- Added ruff and mypy as dev dependencies, both enforced in CI. mypy runs
  `strict` over the package and passes; the 46 findings it started with
  were annotation debt rather than defects, and fixing them removed seven
  `# type: ignore` comments aimed at a checker that had never run. CI now
  pins the Python version instead of letting uv resolve whatever is
  newest, and tests 3.13 and 3.14.
- MAINTENANCE.md now states a cadence. It documented a thorough manual
  procedure with no trigger other than "when something stops working",
  which at roughly twenty migrations a month is too late. The four tests
  that compare against a live installation skip when Wispr Flow is absent
  and CI has no installation, so the weekly cron is a CVE canary and not
  a schema one -- that is now said plainly rather than implied.

0.3.1
-----
- Fixed: verify reported a healthy archive as broken. The count check
  compared the source's row count against every index entry, tombstones
  included, so the first time anything was deleted upstream -- the case
  this tool is built around -- verify printed "archive has problems" and
  exited 1, permanently. Measured on a real archive holding one calendar
  event Wispr Flow had dropped: 2 in source, 3 archived, exit 1. It now
  compares against the archived count minus the records deliberately
  retained, and says "archive is consistent" while still reporting
  "1 deleted upstream, kept here".
- The test named test_a_tombstone_is_not_a_fault did not assert that the
  report was ok, only that the tombstone was counted, which is how the
  bug survived a test written to catch it. Its setup was also
  unreachable: it marked a record absent while the row was still in the
  database. Both fixed, and a second test asserts a genuine count
  mismatch still fails, so reconciling tombstones did not blunt the
  check it lives in.
- A count line now shows the retained figure when there is one, so the
  numbers visibly add up rather than looking like arithmetic that
  failed.

0.3.0
-----
- Added a third backend over Wispr Flow's remote MCP server, and it is the
  only one that reaches meeting content remotely. The REST API cannot:
  meetings, notes and todos are synced by the app through write methods this
  tool does not issue, so over REST they measure 404 and 405. MCP serves all
  three with transcripts, filtered by modification time and paginated.
- The point of it is recovering a transcript the local store no longer has.
  Wispr Flow garbage-collects meeting artifacts -- only one of three meetings
  on the development machine still had its recording -- and MCP still serves
  the text. Verified against a live account: a meeting directory with no
  refined.ndjson and no live.ndjson recovered 32,995 characters, archived as
  a verbatim chunk under raw/mcp/ with a manifest carrying the assembled
  sha256, and rendered as transcript.mcp.md.
- It is a lower-fidelity source and says so in the file it writes. MCP returns
  normalized plaintext with no speaker attribution and no timestamps, where
  the local NDJSON has both. So local wins wherever local has anything: the
  gate reads the archive's own NDJSON from disk rather than trusting
  index.json, and a meeting with either a refined or a live transcript is left
  alone. Live counts because turns with timestamps beat flat prose.
- The MCP server has no dictation access either. Wispr Flow states it in its
  own settings copy, in every locale -- "Wispr MCP has no access to your
  dictation" -- which is the third independent confirmation after the app's
  push/pull resource lists and the REST probe. That question is closed.
- This tool now mints one credential, and the rule it appeared to break is
  restated rather than abandoned. The no-refresh rule exists because rotating
  the borrowed Supabase token would sign the user out of the app being backed
  up. The MCP server is a separate OAuth resource whose authorization server
  is a different issuer, and it answers the borrowed token with 401
  invalid_token, bare and as a Bearer -- so there is nothing to borrow.
  Refreshing a token this tool minted for itself cannot touch the app's
  session. Never refresh a borrowed credential; a minted one is its own to
  manage. Tests assert both halves: cloud_auth still may not contain
  grant_type, and the MCP modules may not reference read_access_token,
  cloud_auth, the Supabase issuer or session.json at all.
- The token lives in ~/.config/wispr-flow-exporter/, mode 0600 in a 0700
  directory, deliberately outside the archive so an archive that is copied or
  shared still carries no credential -- the property that mattered when there
  was no token store at all. `login` and `logout` create and remove it. The
  test asserting no token store could exist was replaced with tests asserting
  where this one may live, rather than deleted.
- The device grant is advertised and does not work. grant_types_supported
  lists urn:ietf:params:oauth:grant-type:device_code, but dynamic registration
  refuses it -- "each value in grant_types must be one of the following
  values: authorization_code, refresh_token" -- and the device endpoint
  answers "Device authorization is not enabled for this application" to a
  client registered anyway. Both measured. So login is authorization code with
  PKCE S256 over a one-shot listener bound to 127.0.0.1, not because a
  listener was preferred but because it is the only grant open to a client
  this tool can register.
- MCP drift is pinned against what the server says about itself, which is
  better than the cloud backend can do: server name, version, negotiated
  protocol, and a digest over each tool's input schema, so a renamed argument
  is reported before a call is made. Severity is about what this tool needs --
  a server that adds tools is additive, one that drops or changes a tool in
  READ_TOOLS is breaking. Measured: wispr-meetings 1, protocol 2025-06-18, 14
  tools advertised, 8 used, pin 12849ed42255.
- MCP is JSON-RPC over POST, so the REST backend's GET-only test cannot extend
  to it and was not made to. What that test protects -- this tool cannot
  change anything upstream -- is protected instead by an allowlist: only four
  JSON-RPC methods are ever sent, and tools/call refuses any name outside
  READ_TOOLS. A write tool the server grows tomorrow is unreachable by
  absence.
- Two ownership rules keep a third writer from corrupting the archive, and a
  test enforces them because they are otherwise only a convention. The MCP
  pass never creates a key under entities["meetings"] and writes exactly one
  field into an existing one, the reserved "mcp" sub-key; and every file it
  writes carries an mcp path component or an .mcp.md suffix. Together they
  make _archive_meeting's up-to-date check invariant under the MCP pass, which
  is what stops the two backends rewriting each other's work forever -- a loop
  whose only symptom would be every meeting rewritten on every run.
- Meetings that exist upstream and not locally are archived under mcp/ with
  their own namespace rather than into meetings/. Writing them there would
  make verify count them against the database and report a mismatch on every
  run, permanently, on a healthy archive.
- The zero-bytes invariant holds for all three backends together: a second
  --source all run wrote no byte and moved no mtime anywhere in a real
  archive. The MCP verbatim store is content-addressed and existence-gated
  rather than compare-then-write, so a nonce in an envelope could not cause a
  rewrite, and no request carries a parameter that moves on its own.
- The default is now --source all: local always, plus cloud and MCP wherever a
  credential exists. Every run prints which backends it will contact before
  contacting any of them, and a backend included by "all" that is not
  authorized is skipped rather than counted as a failure -- naming one
  explicitly still makes a missing credential an error. Each --source now runs
  exactly what it names; previously --source cloud also ran a full local sync
  and required flow.sqlite to exist. "auto" is kept as local-only for anyone
  who wants the previous default.
- Fixed: the test environment isolation did not cover the MCP credential, so
  once a token existed a default sync in the suite would have reached the live
  server with the developer's own authorization -- the same failure mode as
  the guard that exists because a test once copied 15 MB of real audio.
  XDG_CONFIG_HOME and three environment variables are now cleared too, one of
  which, WISPR_ACCESS_TOKEN, had been missing since before this release.
- The response fingerprint machinery moved to drift.py, shared by both remote
  backends rather than living in the cloud one and being imported sideways.
- 471 tests, up from 447.

0.2.0
-----
- The cloud backend never worked. Probed against the live service for the
  first time, all nine endpoints returned 401. The cause was the
  Authorization header: the service accepts the access token bare and
  rejects the RFC 6750 form, so the same token returns 200 sent as
  "Authorization: <token>" and 401 sent as "Authorization: Bearer
  <token>". Every request the backend had ever been able to make was
  refused, and no test could see it because every test ran against a mock
  transport that never checked the header.
- Four of the nine declared endpoints were also wrong, and the errors came
  from how the paths were found. Extracting /api/v1/[a-z0-9_/-]+ from the
  app bundle cannot tell a read from a write and truncates at the last
  matched character, so it invented /api/v1/meetings/ out of the common
  prefix of /api/v1/meetings/<id>/status -- measured 404 -- and it kept
  /api/v1/notes/sync and /api/v1/todos/sync, which answer only to a write
  method and measured 405. Matching the app's own request helper instead
  yields the method with the path, which is the property that decides
  whether this tool may call something at all.
- Dictation history cannot be retrieved from the server, and this is the
  finding rather than an obstacle. Wispr Flow's sync coordinator sorts its
  resources into a pull list and a push list, and history, polish and
  instructHistory are all in the push list; dictation leaves through
  /history/upload and /api/v1/instruct_history/upload with no counterpart.
  Nothing in the bundle reads it back. So when localDataPolicy is
  never_store the text is gone, not withheld, and the tool's honest answer
  is to change the preference in Wispr Flow and archive from that day
  forward. The README says so at the top rather than implying it.
- What the server does hold is the aggregate shadow of that dictation, and
  it is worth having: word counts, total and non-empty durations, day and
  week streaks, words per minute, per-day activity, and a derived profile
  naming the most-used and most-removed word. Five endpoints, all
  archived. Not a sentence anyone dictated.
- ENDPOINTS now carries 18 entries with a status measured against the live
  service rather than inferred, up from 9 inferred. Three of them are
  declared knowing they cannot answer, so a run records the 404 and the two
  405s as standing evidence -- reported as one line, and deliberately not
  counted as failures, because a permanent FAILED on every run is how an
  operator learns to stop reading the word. A change in those statuses is
  reported loudly instead: if /api/v1/notes/sync ever answers a read, that
  is news.
- The zero-bytes invariant did not hold for the cloud backend and now does.
  Two consecutive runs differed in exactly one path, .serverTime, which is
  the server's clock echoed into the calendar responses; hashing it rewrote
  both files every pass. The digest is now taken over a projection that
  drops self-moving fields, exactly as the local backend excludes the
  *PendingPush flags and modifiedAt, while the value is still archived
  verbatim. The cloud zero-bytes test was also measuring one file's mtime,
  which would have passed while index.json was rewritten every run; it now
  compares mtime and contents across the whole archive like the local one.
- Schema drift has a cloud analogue. CLIENT_PIN records the app build the
  endpoint table was validated against, prefs.version, plus a digest over
  the table; each response's structure is fingerprinted into
  .sync-state.json; and the same four verdicts are reported for both
  backends -- ok, additive, breaking, stale_source. Breaking drift still
  archives everything reachable and exits non-zero naming what broke. The
  fingerprint discards every value and is independent of list length, so a
  new meeting is not drift and content cannot reach the state file: a
  dictionary key that does not look like a field name collapses to
  <dynamic>, so a response keyed by UUID cannot record an id.
- Added `schema --source cloud`, the cloud half of the schema command. One
  paced GET per endpoint, writing nothing to the archive or to Wispr Flow,
  reporting status, shape and drift. `--candidates` also probes paths that
  are not archived, which is how a maintainer checks what a new app build
  exposes before adopting any of it.
- Four cloud endpoints paginate and this tool does not page them. Each
  returned one complete page on the account measured, which is a fact about
  that account rather than a guarantee, so the markers are detected and a
  short response is reported. Silent truncation is the one failure an
  archival tool must not have.
- Security: added an endpoint denylist asserted by test, covering
  /api/v1/support/ -- which is account deletion, and which the borrowed
  credential is entitled to call -- along with sandbox-user, enterprise
  administration, contacts and teams. The GET-only rule already made them
  unreachable; the denylist means widening one method cannot quietly make
  them reachable again. /api/v1/referral/ answers and is deliberately not
  archived: it returns the names of people this account referred.
- Both backends now record the Wispr Flow build that produced the archive.
  Nothing did before, so an archive could not say which client wrote it.
- syncCoordinator.timestamps is not an inventory and is no longer described
  as one. Seven of its eleven entries sat at the epoch, including notes and
  todos, which have real data; it is a client-side validator map sent to
  /api/v1/sync/check, and entries advance only when the server returns one.
  The entities at the epoch are driven by the app's older per-entity
  intervals, which keep separate watermarks in the same file --
  prefs.user.lastNoteSyncTime was non-zero, proving notes had synced.
  Reading that map as a taxonomy would understate the account by seven
  entities out of eleven.
- The GET endpoints do accept cursors -- since and cursor on calendar,
  since on the insights heatmap, cursor on notetaker chats -- and the
  client deliberately sends none of them. The archive keeps one verbatim
  snapshot per endpoint, so a delta response would overwrite a whole
  snapshot with a partial one, and the zero-bytes invariant already makes a
  full re-fetch free on disk. The parameter names are recorded next to each
  endpoint so the choice stays visible rather than looking like an omission.
- Verbatim-only archiving stays, and for a better reason than caution. The
  entities with a local shape to map into -- meetings, notes, todos -- are
  exactly the ones no readable endpoint returns, and what remains reachable
  has no local counterpart to merge with. There is nothing for a mapping
  layer to do.
- Fixed: a cloud endpoint that failed once kept last_error forever, because
  the success path never cleared it. It now does, and an entry whose only
  difference is a stale error is rewritten rather than skipped.
- Added MAINTENANCE.md: what to re-check when Wispr Flow updates and in
  what order, why the obvious rediscovery grep is wrong, how to tell a
  readable endpoint from an upload-only one, what cannot be reached and
  why, and the rules that must not be relaxed. This backend is built on an
  interface with no stability promise, and the maintenance burden is the
  price of reaching data that is otherwise unreachable.
- 447 tests, up from 414.

0.1.0
-----
- Initial implementation: a local, incremental archive of Wispr Flow's own
  store. Reads flow.sqlite and the per-meeting NDJSON transcripts and writes
  Markdown plus verbatim JSON, with the undocumented sync API available as a
  second backend for data that never reaches disk.
- A second run with nothing changed upstream writes zero bytes. Not "no
  records written" -- no byte and no mtime anywhere in the archive changes,
  index and sync state included. Three mechanisms hold it: a record whose
  projected digest and artifact fingerprints are unchanged is skipped before
  anything is read or rendered, everything rendered goes through a
  compare-then-write, and an artifact whose size and mtime match its cursor is
  never re-hashed or re-copied.
- The content digest is taken over a projection rather than the whole row.
  Wispr rows carry a dozen columns that flip without the record changing --
  the *PendingPush flags, the *Retries counters, syncedAt, lastUsed, and the
  modification timestamps themselves. Sequelize bumps modifiedAt whenever it
  touches a row, so a background sync that only flips `synced` also moves
  modifiedAt; counting it would rewrite a meeting whose content had not moved
  by one word. The watermark still reads those columns and the digest does
  not, while their values are archived verbatim.
- The database is read while Wispr Flow has it open. The connection is opened
  mode=ro with PRAGMA query_only, and one deferred read transaction spans the
  whole export, so every table comes from a single snapshot and a torn read
  across tables is impossible rather than unlikely. A full run leaves
  flow.sqlite and both sidecars byte-identical.
- The reader never names a column it did not discover. Projections come from
  PRAGMA table_info at runtime, so a column added in migration 150 is archived
  on the next run with no code change, and an undeclared table is archived
  generically. Wispr Flow shipped 11 migrations in August, 21 in July and 25
  in June, so drift is continuous rather than exceptional: additive drift
  warns and completes, and breaking drift still archives everything reachable
  through the raw path while skipping only the affected renderers. For an
  archival tool, failing loud must never mean failing closed.
- Screen context is excluded by name from the SELECT rather than filtered out
  of a SELECT *, so the failure mode of an upstream schema change is a missing
  field rather than a silent screenshot dump. History and FlowLensHistory both
  carry screenshot, axText and axHTML; a rule written against History alone
  would have leaked the other table entirely. Widening that far needs two
  flags, because the columns hold a capture of whatever application had focus
  while you spoke.
- Meeting audio is copied by default. Wispr Flow garbage-collects it: on the
  machine this was developed against only one of three meetings still had its
  upload.ogg, so a recorded pointer would already be dangling. --audio link
  records the path, size and digest instead, and --audio skip records nothing.
- An archive empty because of a preference can prove which preference. When
  localDataPolicy is never_store, dictation is never written to disk at all,
  and a zero row count would otherwise be indistinguishable from a failed
  read. The policy and the date it came into force are recorded in
  .sync-state.json, and doctor reports it before anything is written. This is
  the one failure here that is silent, permanent, and discovered only on the
  day the data is finally wanted.
- Nothing is ever deleted. Deletion has three states rather than a boolean,
  because Wispr tombstones rows in place: present, soft_deleted and absent are
  different facts and are recorded as such. A transcript Wispr Flow has
  dropped is flagged transcript_deleted_upstream and stays exactly where it
  is -- an archive that honoured an upstream deletion would not be an archive.
- The cloud backend borrows a token and never mints one. It reads the access
  token Wispr Flow already holds and never calls the refresh endpoint:
  Supabase GoTrue rotates refresh tokens and detects reuse, so refreshing
  would sign you out of the app being backed up. A test asserts against the
  source of all three cloud modules that no refresh path exists. The client
  issues GET only, responses are archived verbatim because the API is not a
  contract, and it is reached only on an explicit --source cloud or --source
  both -- never because a session happens to exist.
- The cloud backend has not been confirmed against the live service. Its nine
  endpoint paths were read from strings in the application bundle, and every
  test exercises a mock transport or a protocol fake, so its request pacing,
  error handling and credential rules are verified while its response shapes
  are not. It is reached only on an explicit --source cloud or --source both,
  and it archives whatever comes back verbatim, so an unconfirmed shape costs
  a rendering rather than the data.
- Security: archive files are written 0600 and directories 0700 at every
  level. Path.mkdir(parents=True, mode=...) applies its mode to the leaf only,
  which left meetings/, meetings/2026/ and meetings/2026/08/ world-readable in
  a real archive while every leaf was correct; those directory names carry
  meeting titles and participant names.
- Security: meeting ids are validated as canonical lowercase UUIDs before they
  become path components, titles are slugified and length-capped, and every
  archive path resolves through a containment check that refuses absolute
  components as well as traversal. The id, not the slug, is what makes a
  directory safe.
- Security: emitted YAML frontmatter is quoted and escaped, and titles are
  flattened before they reach a Markdown heading. Escaping the frontmatter
  alone was not enough -- a title carrying a newline and "---" opened a second
  block in the body, where escaping does nothing.
- Security: no credential reaches the archive. session.json is read only by
  the cloud backend, the archived account profile carries identity and expiry
  and nothing else, and NoteImages.presignedGetUrl is redacted at read time
  because a signed object URL is a bearer credential in a TEXT column. A test
  records every path opened during a local export and asserts the credential
  file is not among them.
- verify is authoritative rather than approximate, because the upstream is a
  local file: it counts what should exist instead of sampling. It reports
  index entries missing from disk, meeting directories missing from the index,
  payload digests that no longer match, and source records that were never
  archived. render rebuilds every document from archived payloads with no
  source access at all, which is the payoff of writing raw before rendering.
- tests/test_privacy.py enforces the fixture policy: no real name, no absolute
  home path, no JWT-shaped string, and no UUID outside an approved table. It
  caught real mistakes three times during the build. Fixtures are Python
  literals only -- no transcript, audio or image file is ever committed -- so
  the blanket ignores in .gitignore have no exceptions to erode.
- Added CI (pytest plus osv-scanner against uv.lock, on push, pull request and
  weekly), Dependabot configuration, and SECURITY.md.
